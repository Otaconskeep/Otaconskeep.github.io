Architecture

Built on a resource arbiter, not a script

User→ Agent (identity · memory · voice)→ Capability Router→ LLM / TTS / STT Providers

A provider-neutral resource arbiter sits beneath capability routing: workloads request logical CPU/RAM/GPU/VRAM and receive leases that respect placement, priority, and health, rather than agents hardcoding device indexes. Idle model residency can be reclaimed gracefully while active work is protected. Per-voice synthesis settings are configured individually rather than one global profile applied to every voice. This is the same architecture that, at full scale in the private Keep, extends to media, home, and multi-node GPU orchestration. See The Keep.

If something below happens, do not close everything and start over. Setup is still working.

  • Windows SmartScreen may say it protected your PC. Click More info, then Run anyway.
  • Administrator / Yes popup is required. Click Yes. A new Setup window may open, that is expected. The old window can stay open or say setup continues in the new one.
  • Long waits (minutes with a black window and progress text) are normal while Windows enables Linux and Otacon installs. Do not close the window.
  • Restart required does not mean install failed. Save your work, restart, then Setup should show WELCOME BACK and continue. Or double-click the same OtaconsKeep-Setup.bat again.
  • "Updates are underway, please keep your computer on" with the Windows spinner, right after that restart, is Windows itself finishing the Linux/WSL feature install, not Otacon, and not a crash.   • Ubuntu username / password screens are part of Windows Linux setup, not a crash, and not Proxmox.
  • Do not open localhost:5757 until the window says OTACON IS READY. Opening early looks broken even when install is fine.
  • If you see SETUP NEEDS HELP, that is recovery, not a crash. Press R to retry, O for logs, or X to exit. The window should stay open.

Step 2 Copy-paste install

Pick one path. Windows CMD downloads the same Setup file as the button. Ubuntu / WSL runs the Linux installer directly.

Windows · Command Prompt (one line)

  1. Press Windows key, type cmd, open Command Prompt (normal is fine).
  2. Copy this entire line, paste into the black window, press Enter:
    curl -L -o "%USERPROFILE%\Downloads\OtaconsKeep-Setup.bat" "https://otaconskeep.github.io/downloads/OtaconsKeep-Setup.bat" && start "" "%USERPROFILE%\Downloads\OtaconsKeep-Setup.bat"
  3. Approve SmartScreen / Administrator if asked. Leave the Setup window open until it says OTACON IS READY.
  4. Then open http://localhost:5757 in your browser.

Windows · PowerShell (one line)

irm https://otaconskeep.github.io/downloads/OtaconsKeep-Setup.bat -OutFile "$env:USERPROFILE\Downloads\OtaconsKeep-Setup.bat"; Start-Process "$env:USERPROFILE\Downloads\OtaconsKeep-Setup.bat"

Ubuntu / Debian / WSL · terminal (one line)

  1. Open Terminal (or the Ubuntu app on Windows).
  2. Paste this line and press Enter:
    curl -fsSL https://raw.githubusercontent.com/Otaconskeep/otacons-ai-ecosystem/main/install_otacon.sh | bash
  3. When it asks for your password, type your Ubuntu password (nothing will appear), then Enter.
  4. Wait until it prints http://127.0.0.1:5757, then open that address.

Fully manual WSL (no Setup .bat)

  1. Open PowerShell as Administrator and run: 
    wsl --install -d Ubuntu
    Restart if Windows asks.
  2. Open Ubuntu, create a username/password when prompted.
  3. Inside Ubuntu, run the Linux one-liner from above.

  1. This is not a failed install. Save your work and restart the PC.
  2. After reboot, double-click the same OtaconsKeep-Setup.bat again if it does not resume by itself.
  3. You should see WELCOME BACK and it continues from where it left off.

  2. It can take 15–45+ minutes (longer on a hard drive). Drive light flickering = still working.

  1. These are Microsoft’s WSL setup screens, not a crash and not Proxmox.
  2. Create any username you like. Remember the password — it is your sudo password later.
localhost:5757 looks broken / blank
  1. Do not open the site until Setup says OTACON IS READY.
  2. Opening early looks broken even when install is fine. Wait, then refresh.

◐ Not yet fully proven, post-reboot completion

The full "installed and usable after reboot" pass hasn't been independently confirmed end-to-end yet. This is a test-infrastructure limitation, not a known product defect: the automated Windows test lab runs Windows guests with nested virtualization disabled by default (a safety default to avoid a known guest-crash class), and Otacon's setup needs WSL2, which needs nested virt. The lab guest hung at the Windows boot screen after the WSL-enable reboot for that reason. The lab config has since been corrected (nested virt enabled) for future runs, but a corrected lab is not yet a green, repeatable release-gate result.

Release-gate criterion before this is called fully proven: the same download → hostile-path → double-click → WSL → reboot → resume → Core-ready → health-check sequence, green on real Windows 11 hardware or a VM with genuinely proven nested virtualization, not this lab alone.

Advanced: LAN access, repair, uninstall, and other options

Use Otacon from another device on your network

By default Otacon only answers on this machine. To reach it from your phone or another computer, find this PC's LAN IP (ip addr inside Ubuntu, or your router's device list) and visit http://<that-ip>:5757 instead.

Repair

Chat up but voice dead (Piper / TTS)? Do not only re-run Setup hoping it will fix itself, if the site answers, Setup can short-circuit to READY and skip TTS. Use explicit repair: OtaconsKeep-Setup.bat --repair (or choose [ P ] Repair when Setup offers Open / Repair / Reinstall). That restarts the otacon-tts unit, wake task, and spoken preview without wiping data. Full redo: --reinstall / --force. Status: OtaconsKeep-Setup.bat --status. Linux: otacon doctor.

Uninstall auto-start only

Run uninstall_otacon.bat (Windows). It removes the logon task and the systemd service only. Your Ubuntu environment, install folder, and data are untouched.

Optional environment variables (set before running install_otacon.sh)

VariableDefaultWhat it changes
OTACON_INSTALL_DIR~/otacon-ai-ecosystemWhere Otacon gets installed
OTACON_BUILD_NATIVE1Set to 0 to skip building the native .deb app
OTACON_INSTALL_DEB0Set to 1 to also install the built .deb automatically
OTACON_LAUNCH_WIZARD1Set to 0 to skip auto-launching the service at the end
OTACON_INSTALL_STT0Set to 1 to install optional Faster-Whisper speech-to-text
OTACON_RUN_TESTS1Set to 0 to skip the self-test suite (faster, less safe)
OTACON_INSTALL_VOICE_TRAINER1Set to 0 to skip Genome Voice Trainer

Requires sudo to install a handful of system packages (build tools, Python, WebKit libs) and to register the systemd service. The script explicitly refuses to run as the root user itself.
Default Model (included) installs Ollama with a VRAM-tier chat model: qwen2.5:1.5b (CPU/<6GB), 3b (≥6GB), 7b (≥8GB), 14b (≥16GB). Skip with OTACON_INSTALL_DEFAULT_MODEL=0 / OTACON_INSTALL_VOICE_TRAINER=0.
