📚 What You Are Learning

One concept: The Trigger → Condition → Action pattern that powers all Home Assistant automations.

You'll build, test, break, and fix a real automation to master the workflow.

✅ You Should Already Have

  • Home Assistant running with Demo integration (Lesson 3.1)
  • Entities assigned to Areas
  • Understanding of entity IDs

📖 New Words

  • Trigger: WHEN something happens (event that starts automation)
  • Condition: IF this is true (optional check before action)
  • Action: THEN do this (what the automation executes)
  • Trace: HA's debugging view showing automation execution path

🏗️ Architecture Picture

┌─────────────────────────────────────────────────────────────┐ │ AUTOMATION FLOW DIAGRAM │ ├─────────────────────────────────────────────────────────────┤ │ │ │ Example: "Turn on hallway light when door opens at night" │ │ │ │ 1. TRIGGER (When this happens) │ │ ┌────────────────────────────────────┐ │ │ │ State Change: │ │ │ │ binary_sensor.front_door │ │ │ │ from: off → to: on │ │ │ └────────────────────────────────────┘ │ │ ↓ │ │ 2. CONDITION (If this is true) │ │ ┌────────────────────────────────────┐ │ │ │ Check: Is it after sunset? │ │ │ │ sun.sun = below_horizon → TRUE │ │ │ └────────────────────────────────────┘ │ │ ↓ │ │ 3. ACTION (Then do this) │ │ ┌────────────────────────────────────┐ │ │ │ Service call: │ │ │ │ light.turn_on │ │ │ │ target: light.hallway_light │ │ │ └────────────────────────────────────┘ │ │ ↓ │ │ 💡 Light turns on! │ │ │ │ If condition is FALSE (daytime), automation stops. │ │ No action runs. │ │ │ └─────────────────────────────────────────────────────────────┘

🔧 Lab Steps: Build Your First Automation

Open Automation Editor

Settings → Automations & Scenes → Create Automation → Create new automation

You'll see a blank automation template with Trigger / Condition / Action sections.

Name Your Automation

Top of page: Name = "Demo: Turn on bedroom light at sunset"

Add a Trigger (Sun Trigger)

Click "Add Trigger" → Search "sun" → Select "Sun"

Configure:

  • Event: Sunset
  • Offset: 0 (trigger exactly at sunset)

Add an Action (Turn On Light)

Scroll down → Click "Add Action" → Search "light" → "Turn on lights"

Choose target:

  • Click "Choose entity"
  • Select light.bed_light (from Demo integration)

Save the Automation

Click "Save" at top right.

Your first automation is now active!

Test Without Waiting for Sunset

Click the three dots menu → "Run"

This manually triggers the automation.

Check Overview dashboard → light.bed_light should turn on!

View Automation Trace

In the automation editor, click "Traces" (top right)

You'll see the execution path:

  • Green boxes = steps that ran
  • Red boxes = errors (if any)
  • Gray boxes = conditions that blocked execution

Add a Condition (Time-Based)

Edit your automation → Add Condition → Time

Configure:

  • After: 18:00 (6 PM)
  • Before: 23:00 (11 PM)

Save → Run again

Result: If you run outside 6-11 PM, light won't turn on (check trace — condition will be red).

Build a Second Automation (State-Based)

Create new automation: "Demo: Turn off lights when away"

Trigger: State → Entity: person.demo → To: "not_home"

Action: Turn off lights → Choose ALL demo lights in your bedroom area

Save and test by manually changing person state in Developer Tools.

Practice: Break and Fix

Intentionally break the automation:

  1. Change light entity to a non-existent ID (e.g., light.fake_light)
  2. Try to run the automation
  3. Check trace → See the error!
  4. Fix the entity ID → Run again → Should work

This is how you debug real automations!

📚 Understanding Triggers, Conditions, Actions

Triggers (Required — at least one):

  • State: Entity changes state (light.bedroom from off → on)
  • Time: Specific time or interval (every day at 7 AM)
  • Sun: Sunrise or sunset
  • Numeric state: Sensor crosses threshold (temp > 75°F)
  • Event: HA system events (startup, shutdown)

Conditions (Optional — zero or more):

  • State: Check if entity is in certain state
  • Time: Only run during certain hours
  • Numeric state: Check sensor value
  • Zone: Check if person is home/away
  • Template: Custom logic (advanced)

Actions (Required — at least one):

  • Service calls: Turn on/off lights, send notifications
  • Delays: Wait X seconds before next action
  • Choose: If-then branching (advanced)
  • Repeat: Loop actions (advanced)
⚠️ Common mistake: Forgetting that conditions are CHECKS, not triggers. If condition is false when trigger fires, automation stops.

🔧 Troubleshooting Decision Tree

Problem: Automation doesn't run when trigger fires

→ Check automation is enabled (toggle in automation list)
→ Check trace for red condition boxes (condition blocked it)
→ Verify entity ID in trigger matches actual entity

Problem: "Entity not found" error in trace

→ Entity ID must match EXACTLY (case-sensitive)
→ Check entity still exists: Developer Tools → States
→ If entity was renamed, update automation

Problem: Automation runs but nothing happens

→ Check action service call is correct (e.g., light.turn_on)
→ Verify target entity is controllable (not a sensor)
→ Look for error messages in trace action step

Problem: Can't find entity when creating automation

→ Entity might be hidden: Settings → Entities → Show disabled
→ Integration might be offline: Settings → Devices & Services
→ Try typing entity ID manually instead of clicking
