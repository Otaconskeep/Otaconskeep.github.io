Lesson 3.1: HA Beginner — Device / Entity / Area / Integration

BABY

📚 What You Are Learning

One concept: The Home Assistant hierarchy — Devices contain Entities, Entities belong to Areas, Integrations connect everything.

Master this mental model BEFORE writing automations.

✅ You Should Already Have

  • Docker working (Unit 1)
  • Basic understanding of smart home devices (lights, sensors)
  • A computer that can run Home Assistant

📖 New Words

  • Home Assistant (HA) — Open-source home automation platform
  • Device: Physical hardware (e.g., a smart light bulb)
  • Entity: One control point on a device (e.g., light.living_room_lamp)
  • Area: Physical location grouping (e.g., "Living Room")
  • Integration: Software bridge to connect devices/services to HA

🔧 Lab Steps: Install Home Assistant and Learn the Hierarchy

Install Home Assistant Container

Create ~/docker/home-assistant/docker-compose.yml:

version: "3.8"

services:
  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    container_name: homeassistant
    environment:
      - TZ=America/New_York
    volumes:
      - ./config:/config
    ports:
      - "8123:8123"
    restart: unless-stopped
    privileged: true
    network_mode: host
⚠️ Note: network_mode: host is required for HA to discover local devices. This bypasses Docker network isolation. 
docker compose up -d

Complete Setup Wizard

Open: http://localhost:8123 (or http://SERVER-IP:8123)

  1. Create your admin account (username + strong password)
  2. Set location (used for weather, sunrise/sunset)
  3. Choose system of measurement (metric/imperial)
  4. Skip device discovery for now (we'll do it manually)

Explore the Dashboard

You'll see a basic dashboard. Don't worry if it's empty — we'll add devices!

Key sections to notice:

  • Overview: Main dashboard with entity cards
  • Settings: Configuration and integrations
  • Developer Tools: For testing automations

Add Your First Integration (Demo)

Let's add the "Demo" integration to create fake devices for learning:

  1. Settings → Devices & Services → Add Integration
  2. Search for "Demo"
  3. Click "Demo" → Click "Submit"
  4. Wait a few seconds

HA will create demo lights, sensors, switches, etc!

Explore Devices

Settings → Devices & Services → Demo Integration → Click "Devices"

Click on any device (e.g., "Bedroom Light")

You'll see:

  • Device info: Manufacturer, model, firmware
  • Entities: List of entities this device provides
  • Area: Which room it's assigned to

Explore Entities

Settings → Devices & Services → Demo Integration → Click "Entities"

This shows ALL entities from Demo devices.

Click on an entity (e.g., light.bed_light)

You can:

  • Rename it
  • Assign it to an Area
  • Hide it from the UI
  • See its history

Create Areas

Settings → Areas, Labels & Zones → Areas → Add Area

Create these areas:

  • Living Room
  • Bedroom
  • Kitchen

You can add an icon and image for each area.

Assign Entities to Areas

Go back to Settings → Devices & Services → Demo → Entities

For each entity:

  1. Click the entity name
  2. Click the gear icon ⚙️
  3. Select an Area from the dropdown
  4. Click "Update"

Test Entity Controls

Return to Overview dashboard

You should now see entity cards grouped by Area!

Click a light entity → Toggle it on/off

Click a sensor entity → See current value

This is entity control — the foundation of HA!

Use Developer Tools

Developer Tools → States

This shows the internal state of EVERY entity.

Find light.bed_light → See state: "on" or "off"

This is what automations read and modify!

📚 Understanding the HA Mental Model

1. Integration (The Bridge):

Software that connects HA to devices or services. Examples:

  • Zigbee2MQTT — connects Zigbee devices
  • Philips Hue — connects Hue lights
  • MQTT — connects custom IoT sensors
  • Weather — gets forecast data

2. Device (The Hardware):

A physical or virtual device managed by an integration.

One device can provide multiple entities.

3. Entity (The Control Point):

The actual thing you control or read in automations.

Entity ID format: domain.object_id

Examples:

  • light.living_room_lamp — controllable light
  • sensor.bedroom_temperature — read-only sensor
  • switch.coffee_maker — on/off switch

4. Area (The Location):

Logical grouping of entities by physical room.

Used for voice commands ("turn off living room lights") and dashboards.

💡 Key insight: In automations, you control ENTITIES, not devices. Always think in terms of entity IDs!

🔧 Troubleshooting Decision Tree

Problem: Home Assistant not accessible at :8123

→ Check container is running: docker ps | grep homeassistant
→ Check logs: docker logs homeassistant
→ First boot takes 2-3 minutes to start — wait for "Home Assistant initialized"

Problem: Can't find Demo integration

→ Search for "demo" (lowercase) in Add Integration dialog
→ Restart HA if integration list doesn't load: Settings → System → Restart
→ Check internet connectivity (HA downloads integration list)

Problem: Entities not showing on dashboard

→ Check entity is not hidden: Settings → Entities → Show hidden
→ Add entities manually to dashboard: Edit Dashboard → Add Card → Entity
→ Refresh browser (Ctrl+F5)
