Goal / What you are learning

One concept: a VM is a full virtual computer (own kernel); a container shares the host kernel and packages an app. Homelabs often run containers inside VMs/LXCs on a hypervisor like Proxmox.

After this lesson you can: sketch where Docker sits in a typical Proxmox homelab; decide "VM vs container" for a simple workload.

📖 New words

  • Hypervisor — runs VMs
  • VM — full guest OS
  • Container — app isolation, shared kernel
  • CT / LXC — Proxmox Linux container
  • Proxmox — popular homelab hypervisor

📋 Baby-steps by OS

Windows (WSL2 + Docker)

You already run a lightweight VM (WSL2). Docker Desktop/Engine rides on that. Mental model: Windows → WSL2 VM → Docker containers.

Linux (Ubuntu + Docker)

Docker Engine runs on the host kernel. Optional later: put this Ubuntu inside a Proxmox VM for snapshots/isolation.

Merge

Both paths: containers are not a replacement for backups or for workloads that need a different kernel/OS.

🔧 Troubleshooting decision tree

docker run fails?
├─ Choose Path incomplete → go back
├─ Alpine pull blocked → check DNS/internet; retry
└─ Permission denied → docker group / Desktop running

uname differs wildly / unexpected arch?
└─ You may be on a remote context (`docker context ls`); switch to default local
