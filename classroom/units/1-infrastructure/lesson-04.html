Lesson 1.4: Docker Playground & Disposable Containers

BABY

📚 What You Are Learning

One concept: Embrace the disposable container mindset — test, break, delete, recreate.

You'll learn to use Docker as a playground for testing software WITHOUT cluttering your host OS with packages and configs.

✅ You Should Already Have

  • Docker and Docker Compose working (Lessons 1.1–1.3)
  • Comfortable with docker run and docker compose commands

📖 New Words

  • Ephemeral container: A container that gets deleted after you're done testing
  • --rm flag: Automatically remove container when it stops
  • Interactive mode (-it): Connect your terminal to the container's shell
  • Docker exec: Run commands inside a running container

🔧 Lab Steps: Practice Disposable Containers

Launch a Throwaway Ubuntu Shell

docker run --rm -it ubuntu:22.04 bash

Flags explained:

  • --rm — Remove container after exit
  • -it — Interactive terminal
  • ubuntu:22.04 — Image name and tag
  • bash — Command to run (opens Bash shell)

You're now inside a Ubuntu container!

Install Software in the Container

Inside the container shell:

apt update
apt install -y curl htop net-tools

Test the tools:

curl https://ifconfig.me
htop  # Press q to quit

Exit and Watch It Disappear

exit

Back on your host terminal. Now check running containers:

docker ps

Nothing! The container is gone thanks to --rm.

Check stopped containers:

docker ps -a

Still nothing! Completely cleaned up.

Try a Different Distro Instantly

Want to test something on Alpine Linux?

docker run --rm -it alpine:latest sh

Install packages with apk (Alpine's package manager):

apk add curl bash
bash  # Switch to bash shell
exit  # Exit bash
exit  # Exit container

Test Network Tools

Need to test DNS or connectivity?

docker run --rm -it nicolaka/netshoot

This image has ALL network debugging tools pre-installed:

nslookup google.com
ping -c 3 1.1.1.1
traceroute 8.8.8.8
exit

Execute Commands in Running Containers

Start a long-running container in background:

docker run -d --name test-nginx nginx:alpine

Execute a command inside it:

docker exec test-nginx ls -la /usr/share/nginx/html

Open an interactive shell:

docker exec -it test-nginx sh

Make changes, then exit. Container keeps running!

exit

Clean up:

docker stop test-nginx
docker rm test-nginx

One-Shot Commands

Run a single command and auto-cleanup:

docker run --rm alpine:latest echo "Hello from Docker!"

Check Python version without installing Python on host:

docker run --rm python:3.11 python --version

Generate a random password:

docker run --rm alpine:latest sh -c "head /dev/urandom | tr -dc A-Za-z0-9 | head -c 20 ; echo"

🧪 Practice Exercises

Exercise 1: Test a Web Server

  1. Run: docker run --rm -p 8888:80 nginx:alpine
  2. Open browser: http://localhost:8888
  3. See nginx welcome page
  4. Press Ctrl+C in terminal to stop
  5. Container is automatically removed!

Exercise 2: Test Software Before Installing

Want to try Node.js 18 vs 20?

docker run --rm -it node:18-alpine node --version
docker run --rm -it node:20-alpine node --version

No permanent Node.js installation on your host!

Exercise 3: Debug Network Issues

docker run --rm nicolaka/netshoot nslookup your-domain.com

Perfect for troubleshooting DNS from inside Docker's network.

💡 Why This Matters for Homelab

Testing Before Committing

Before adding a new service to your docker-compose.yml, test it in a disposable container first:

  • Does the image work?
  • What environment variables does it need?
  • Which ports does it expose?

Clean Debugging Environment

When troubleshooting, spin up a fresh container to eliminate config pollution from previous tests.

Learning New Tools Risk-Free

Want to learn PostgreSQL? Spin up a container, break it, delete it, try again. Your host OS stays pristine.

💡 Pro tip: Use docker run --rm for testing. Use docker-compose.yml for production services you want to keep running.

🔧 Troubleshooting Decision Tree

Problem: "Unable to find image 'ubuntu:22.04' locally"

→ This is NORMAL! Docker downloads the image automatically on first run
→ Wait for the pull to complete, it only happens once
→ Subsequent runs use the cached image (instant start)

Problem: "docker run" exits immediately instead of opening a shell

→ Make sure you include -it flags for interactive shell
→ Specify a shell command: bash, sh, or /bin/bash
→ Example: docker run --rm -it ubuntu bash

Problem: Container not deleted after exit (still shows in docker ps -a)

→ Did you forget the --rm flag?
→ Manually clean up: docker rm CONTAINER-ID
→ Clean all stopped containers: docker container prune

Problem: "docker exec" says "container is not running"

→ Check container status: docker ps
→ Container must be running to use exec
→ Start it if stopped: docker start CONTAINER-NAME
