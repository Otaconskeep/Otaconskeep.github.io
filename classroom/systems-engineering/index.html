00 // Three paths, one spine

Foundations, then Practicing Systems Engineer, then MBSE / Advanced Analysis

Every course sits on a single 20-course spine (SE-101 through SE-120), plus a six-course SysML deep dive for the modeling and analysis path. You do not have to take all three paths (Foundations alone is a complete, useful grounding), but each later path assumes the one before it.

PATH 1

Foundations

SE-101 through SE-108. What a system is, the life cycle, requirements, traceability, verification and validation with a full VCRM, risk management, architecture, and interfaces. Everything downstream depends on this path.

PATH 2

Practicing Systems Engineer

SE-111, SE-113 through SE-120. Trade studies, reliability and safety analysis, integration and test, technical management, systems of systems, digital engineering, the wider Industrial and Systems Engineering body of knowledge, and the capstone.

PATH 3

MBSE / Advanced Analysis

SE-109, SE-110, and SE-112, plus SE-121 through SE-126 for the full SysML sequence. One model, built across the whole sequence, instead of a throwaway diagram in a single lecture.

01 // The idea everything else hangs on

The Verification Cross-Reference Matrix

A VCRM maps every requirement to the method and level used to verify it: inspection, analysis, demonstration, or test. It connects the requirement to a test level, a responsible party, and a specific test identification. This is not taught as one spreadsheet in one class: it is the spine of the whole Foundations path.

Need→ Requirement→ Architecture→ Design→ Verification Requirement→ VCRM→ Test→ Evidence→ Acceptance
Where you build it: SE-105 (Verification & Validation + VCRM) introduces the full matrix. SE-120 (Capstone) is where your own VCRM has to actually hold up against a real test plan.

02 // The spine

Need → requirement → architecture → model → verification → a professional package

CONOPS→ Stakeholder needs→ Requirements→ RTM→ Architecture→ SysML model→ Interfaces→ Risk / FMEA→ Trade study→ VCRM→ Test plan→ Verification results→ Capstone package

The capstone system is a fictional disaster-response autonomous drone. By SE-120 you have produced, piece by piece across the whole Academy, a miniature real Systems Engineering Technical Data Package: CONOPS through verification evidence.

05 // Path 3: MBSE / Advanced Analysis

SE-109, SE-110, SE-112, and SE-121 through SE-126

SysML v2 is a real, formally published OMG standard, not a footnote, so it gets a full sequence of courses instead of one. Students build a single model across all of them rather than throwing each one away. Every SysML course carries a real SE-number, not a separate "SysML I–VI" naming track, so it's never unclear whether these are courses, modules, or something else. SE-112 gets the same treatment for data: a real progression from scatter plots to Design of Experiments, not "make a heatmap and call it insight."
